# CLAUDE.md

Инструкции для Claude Code при работе в этом репозитории.

## О проекте

Скрипт, который проверяет электронный дневник **Librus Synergia** и присылает новые уведомления (домашние задания, объявления, позже — оценки) в **Telegram-канал**.

**Текущий этап (MVP): только один ребёнок — Даниил (старший).**
Второй ребёнок и второй Librus-логин — сознательно не подключаем на этом этапе. Код можно писать так, чтобы потом было легко добавить второго ребёнка (не хардкодить "один аккаунт" в самой логике), но фактически подключать и тестировать — только один аккаунт Даниила.

Полный план и обсуждённые решения — в файле `plan-librus-telegram.md` (в Project "Librus notifications in Telegram"), если он есть рядом в репозитории или доступен через Projects.

## Стек

- Python **3.10+** (обязательно — `librus-apix` 1.5.1 требует 3.10+; на машине изначально стоял системный Python 3.9.6, поставлен `python@3.12` через Homebrew, virtualenv создаётся на нём)
- [`librus-apix`](https://github.com/RustySnek/librus-apix) — неофициальная, но активно поддерживаемая библиотека для Librus Synergia. Логин по логину/паролю (НЕ по cookie из браузера — они протухают за день).
- `python-dotenv` — для загрузки `.env` в `main.py` (единственное отступление от изначального минимального списка зависимостей, взято ради надёжного парсинга `.env` вместо самодельного парсера)
- Telegram Bot API (обычные HTTP-запросы, `requests`) — доп. библиотека вроде `python-telegram-bot` не нужна, отправка сообщений в канал — это один POST-запрос.

### Реальный API `librus-apix` (проверено на версии 1.5.1)

```python
from librus_apix.client import new_client, Client, Token
client: Client = new_client()
client.get_token(username, password)  # логин; кидает MaintananceError / AuthorizationError

from librus_apix.homework import get_homework, homework_detail
homework = get_homework(client, date_from, date_to)  # date_from/date_to: "YYYY-MM-DD", диапазон ~месяц
# Homework: lesson, teacher, subject, category, task_date, completion_date, href
# href — единственный стабильный уникальный ключ (числового id нет)
# ВАЖНО (контринтуитивное именование полей в библиотеке, проверено на реальных данных):
#   h.lesson  = название предмета, например "Matematyka"
#   h.subject = тема/описание задания (НЕ название предмета!)
details = homework_detail(client, h.href)  # полный текст задания (для этого и нужен доп. запрос)

from librus_apix.announcements import get_announcements
announcements = get_announcements(client)
# Announcement: title, author, date, description — тоже без id/href,
# для дедупликации используется sha256(title|author|date)
```

## Переменные окружения

Хранить в `.env` (добавить в `.gitignore`), пример — в `.env.example`:

```
LIBRUS_USERNAME_DANIIL=...
LIBRUS_PASSWORD_DANIIL=...
TELEGRAM_BOT_TOKEN=...
TELEGRAM_CHAT_ID=...
```

Имена переменных уже с суффиксом `_DANIIL`, чтобы при добавлении второго ребёнка не пришлось переименовывать существующие.

## Логика дедупликации

1. Получить список текущих уведомлений (домашние задания / объявления) через `librus-apix`.
2. Сравнить с ID/хэшами в `state/seen_daniil.json`.
3. Новые — отправить в Telegram, затем добавить в `state/seen_daniil.json` и сохранить файл.
4. Если `state/seen_daniil.json` не существует (первый запуск) — считать текущие уведомления уже "виденными" и НЕ слать их все разом в канал (иначе при первом запуске улетит вся история). Отправлять только то, что появится после первого запуска.

## Формат сообщений в Telegram

Уточнено с пользователем: сообщение о домашнем задании — заголовок **"НОВОЕ ДОМАШНЕЕ ЗАДАНИЕ"** жирным капсом, затем ровно три поля с оригинальными подписями как на сайте Librus (без перевода на русский):
- `Przedmiot` — название предмета (`h.lesson` из списка заданий, например "Matematyka")
- `Termin wykonania` — дедлайн **с днём недели** (`h.completion_date` из списка заданий, например "2026-09-08 wt."; поле `Termin wykonania` внутри `homework_detail()` день недели не содержит — обрезанная дата, поэтому день берём из списка, а не из деталей)
- `Treść` — полный текст задания (из `homework_detail()`, соответствует вкладке "Podgląd" на сайте)

Поля `Temat`/`Zajęcia edukacyjne`/`Kategoria`/`Data udostępnienia` из `homework_detail()` в сообщение не идут.

Сообщения шлются через `parse_mode=HTML` (нужен для жирного заголовка `<b>...</b>`). Из-за этого весь текст, пришедший из Librus (тема, содержание задания, объявления), обязательно экранируется через `html.escape()` перед вставкой в сообщение — иначе символы `<`, `>`, `&` в тексте учителя могут сломать разметку или вызвать ошибку Telegram API.

## Хостинг и расписание

Решено: скрипт хостится в **Docker-контейнере на Raspberry Pi мужа** (постоянно включённое устройство — в отличие от ноутбука, который может спать/выключаться). Локальный `cron` на macOS не взлетел (нужен Full Disk Access для Terminal, который нельзя выдать программно) — от этого варианта отказались в пользу Docker.

Расписание — **каждые 2 часа с 8:00 до 20:00** (8, 10, 12, 14, 16, 18, 20) — реализовано не системным cron, а простым циклом внутри контейнера, `scheduler.py`: раз в 30 секунд проверяет текущее время и запускает `main.py`, если сейчас начало одного из этих часов. Часовой пояс контейнера задан явно (`TZ=Europe/Warsaw` в `Dockerfile`) — если Raspberry Pi физически в другом часовом поясе, поправить эту переменную.

Деплой (на самом Raspberry Pi, не на macOS — `librus-apix` тянет C-расширения типа `lxml`, лучше собирать сразу под архитектуру Pi):
```
# скопировать весь проект на Pi (без .venv — он не нужен и не переносится)
# создать/скопировать .env с реальными значениями рядом с docker-compose.yml
docker compose up -d --build
docker compose logs -f          # смотреть логи (login/fetch/send, ошибки)
```
`state/seen_daniil.json` примонтирован как volume (`./state:/app/state`) — переживает пересборку и перезапуск контейнера, дедупликация не сбрасывается.

## Как проверять работу

- Логин и получение домашних заданий — должно быть видно в консоли (print/лог), прежде чем подключать Telegram
- Отправку в Telegram проверять сначала вручную (например, curl к `sendMessage`), потом уже из скрипта
- Не коммитить реальные токены/пароли; если случайно закоммичены — считать их скомпрометированными и перевыпустить (для Telegram-бота — `/revoke` у @BotFather, для Librus — сменить пароль)
